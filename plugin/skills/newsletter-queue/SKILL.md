# Newsletter queue

Turn a sending plan into an ordered queue of drafts with a pre-send checklist each.

## The rule that matters more than the queue

**Staged is not sent.** Every item here ends as a draft plus a checklist; the publish button belongs to a human with the credentials. A queue that sends itself is a bug, not a feature.

## What to read, in this order

1. **Inventory** — drafts, scheduled items, welcome-series state, subscriber counts per segment.
2. **Order** — sequence by date with dependencies (series order, embargoes, event ties).
3. **Pre-send checklist per item** — subject, preview text, links verified, segment selected, unsubscribe present, test send reviewed.
4. **Welcome series** — new-subscriber path checked end to end: trigger, delay, each step's draft exists.

## Output

Ordered queue table (date, item, segment, checklist state) plus a per-item go/no-go. No-go names the missing piece, never a vague "not ready."

## Boundaries

- Drafts and checklists only. Never send, schedule-send, publish, or touch subscriber data or credentials.
- Never invent subscriber counts or engagement rates: unsourced numbers are unmeasured and fail the item to no-go.
